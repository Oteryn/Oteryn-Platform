## Root cause and fix

PostgreSQL advisory keys are scoped to a database, not a search_path/schema.
At f74eb95f, staff target preparation acquires exclusive 64002 before target
rows/accounts. Ordinary bazaar operations and statement triggers acquire shared
64002. The delta lock-order regression deliberately retains shared 64002 while
waiting on another actor. Parallel tests in unrelated schemas therefore join
the same lock queue and consume each other's unchanged three-second mutation
budget. This is a fixture isolation defect, not a production hierarchy defect.

A single `oteryn-db` test-support guard now owns an independent session advisory
lock (test-only key 684326110016002). Database test entry points acquire it before
fixtures, transaction deadlines, and scenario elapsed-time measurements, retaining
it through cleanup. The session is dedicated, never pooled; dropping the guard
closes it even after a panic. A shared asynchronous process mutex limits waiting
sessions to one per binary; the database session lock coordinates different
binaries/crates using the same database. Internal spawned actors remain concurrent.
The feature is enabled only in dev-dependencies; normal production builds do not
include the helper.

The audit also found the same cross-schema hazard in the database-global 71010
RBAC fence (admin, support, content and character bootstrap), the
22005160000 publication fence (bazaar and characters), and the fixed `(29,1)`
store delivery key. Character restore rows themselves are schema-local; the
character publication fence and store advisory key are database-wide.
Database fixture test modules in all requested suites participate in
the same guard, including macro-generated support authorization-wait tests and
bazaar runtime tests. Re-exec fixtures (support staff, character overview, and
content media processing) acquire only in the child doing the database work,
past the re-exec launch branch; the parent never acquires the guard while waiting
for its child. The synchronous media test acquires inside its async runtime.
Some transport/unit cases colocated in database fixture
modules also participate so that module entry points follow one consistent rule.
Pure in-memory bazaar stats tests remain independent. The final entry-point audit
also includes the PostgreSQL game, coin-port lock-order, and notification suites.

No production lock acquisition, migration, timeout, three-second budget, test
assertion or test selection was weakened. The RBAC README hierarchy is unchanged.
