## Reading the inventory

- `{lang}` is `pl` or `en`. Explicit unprefixed paths also appear where registered. Ordinary Axum GET handlers have implicit HEAD support. The method column shows application methods. Counts treat distinct reads, submissions and separately dispatched actions as functions. Aliases and alternate methods on the same handler count once. Private peer exchanges are listed below as dependencies, except the Wallet wire which is the direct native coin interface. Staff CLI commands have no HTTP method.
- Every named Boolean feature gate in the tables defaults **off** when absent unless a row says otherwise. “None” means no feature gate. Database, session, host, origin, provider, dataset and authority prerequisites still apply. Production labels use the supplied flag set and Game/store/payments-off policy. “Deployment setting unverified” means the supplied profile does not settle that core identity, support or staff setting. An enabled flag can serve an empty, stale or refusal state.
- Game **read** includes Game-fed projections and authoritative reads. **Mutation** includes a queued Game command or receipt exchange. The Game boundary is generally `/internal/v1`, with the `/internal/v2` projection and command exceptions listed below. Imported static catalogs and published assets are local reads.
- Staff means a verified session on the configured staff host with MFA, `OTERYN_ADMIN_PANEL` and `admin.access`, plus the listed permission and any scope or step-up checks. The migration role map below gives seeded role keys. Custom roles and scoped grants can change a live decision. Player means an authenticated web session unless a bearer, device or challenge proof is listed.
- E2E links are existing feature specs under `portal-rs/e2e/specs`. A linked suite can assert a page, refusal or simulated Game result for the feature. The [route smoke matrix](../../portal-rs/e2e/specs/routes.spec.mjs) is additional status/markup coverage for entries in the [checked-in manifest](../../portal-rs/e2e/inventory.json). Rust links include handler, service and fixture tests where applicable. An em dash means no specific test was identified in that column. No test execution or live feature verification is implied.

Growth rankings serve yesterday, week, month, record, oldest, anniversaries, name changes, transfers and sold. The character statistics tabs and comparison differ from public character profiles. Enabled collection and Atlas bestiary routes use unavailable ownership or progress adapters. [Character creation gates](../../portal-rs/crates/characters/src/create_web/http.rs#L65), [character service gates](../../portal-rs/crates/characters/src/services/browser.rs#L313), [collection wiring](../../portal-rs/crates/minigames/src/collection/http.rs#L133), [bestiary wiring](../../portal-rs/crates/atlas/src/bestiary/web.rs#L60).
