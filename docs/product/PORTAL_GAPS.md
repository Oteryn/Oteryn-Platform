# Rust portal launch gaps

This backlog ranks work by launch value for an Open Tibia-style server. Signup, entry to Game, safety and staff response lead the queue. Public discovery, editorial operations and player conveniences follow. Commercial and advanced Game functionality depend on separate qualification. The companion [feature inventory](PORTAL_FEATURES.md) lists the current routes and controls.

Findings are from `origin/main` at [`7847cf7de919`](https://github.com/Oteryn/Oteryn-Platform/tree/7847cf7de91957d4317e7693d31d049b8f1c5f8e). The plan establishes intended scope, and runtime composition, migrations, templates and tests establish implementation. An accepted contract, a set flag and a simulated receipt each prove a different stage. Production states use the supplied flags. Game producer availability and live configuration remain unverified. The retired Laravel migration tasks T38–T38e are out of product scope. [Plan status and dependencies](../architecture/OTERYN_PORTAL_RUST_PLAN.md#L570), [task table](../architecture/OTERYN_PORTAL_RUST_PLAN.md#L722), [panel matrix](../architecture/PANELS_CAPABILITY_MATRIX.md), [Game auth threat model](../architecture/GAME_AUTH_THREAT_MODEL.md), [native protocol threat model](../architecture/OTERYN_NATIVE_PROTOCOL_THREAT_MODEL.md), [security invariants](../../AGENTS.md).

Each row has one primary dependency. “Needs Game contract” includes ratification, delivery under an already accepted contract, or composed release qualification. S is a focused change, M is a cross-surface workflow, and L spans multiple authorities or substantial product work. Acceptance tests are proposed and give a success, refusal and bad-input case.
