# Player, admin and GM panel capability matrix

Governing issue [#2010](https://github.com/Oteryn/Oteryn-Platform/issues/2010). Code baseline is [`origin/main` at `64ace4dad05e`](https://github.com/Oteryn/Oteryn-Platform/tree/64ace4dad05ec55b15034d72b2b244aa11e05099). Browser coverage follow-up is tracked in [#2002](https://github.com/Oteryn/Oteryn-Platform/issues/2002).

**done** means the panel has the core actor-to-result path. **partial** means one layer works but the complete capability still needs a panel action, a supported dependency, a result path or a material workflow step. **missing** means the panel has no implementation of the operation. Missing rows cite the closest relevant route or handler. Feature flags and Game availability still govern real use. E2E entries identify the assertions present on this revision, including page-only, refusal and simulated Game coverage. They are a static inventory of specs. Staff permissions are listed in addition to the enclosing staff access, host and MFA guard where it applies. “Owner” means the account from the browser session and resource ownership checks where applicable.

A “local” navigation entry starts inside a feature, dashboard or detail page. A “No” entry can still have a directly reachable URL. For missing capabilities the channel is the intended owner or transport. Contract status refers to the scope stated by the linked file. “Owner decision” and “implemented” are annotated when the file uses that wording. ADM-01 uses the pinned [operation and envelope sources](../../portal-rs/crates/admin/src/control/fixtures/admin-control-v1/SOURCE.md) and the [ratified framing note](../contracts/ADMIN_CONTROL_AGENT_WIRE_RATIFICATION.md). The five staff commands also use the pinned [staff-action fixtures](../../portal-rs/crates/admin/src/control/fixtures/staff-actions-v1/SOURCE.md).
